# 눈길 발자국 — 프롬프트 설계서

버전 1.0 · 2026-11-16 · 기획서 1.1 기준

## 0. 이 문서

- 쓰임: AI 코딩 도구(Claude Code 기준. Codex도 같은 프롬프트로 된다)에 차례로 줄 프롬프트 19개와, 단계마다 직접 확인할 것을 적었다.
- 기획서(`docs/눈길발자국_기획서.md`)는 무엇을 만드는지의 기준이고, 이 문서는 만드는 순서다. 둘이 다르면 기획서가 맞다.
- 규칙은 이미 만들어져 있다. 참조 엔진(`engine.ts`)이 정답, 안내 문장, 문제, 별, 잠금을 계산하고, 검증 자료와 대조되어 있다. AI 도구가 만들 것은 화면, 소리, 저장이다.
- 8단계에서 한 번 배포해서 실제 폰으로 소리를 듣는다. 폰 스피커에서 악센트와 마르카토가 구분되는지가 아직 확인하지 못한 가장 큰 것이라 앞에 두었다.
- 미리 해 본 범위는 부록 2에 있다. 1단계는 실제로 해 봤고, 2단계 가운데 글꼴과 견본 화면을 해 봤다. 그 뒤는 설계만 했다.

## 1. 준비 (직접 하는 일)

1. `snowpath-kit.zip`을 더블클릭해서 푼다. `snowpath` 폴더가 생기고 그 안에 `docs` 폴더가 있다.
2. `snowpath` 폴더를 평소 개발 폴더로 옮긴다. 폴더 이름은 바꾸지 않는다(한글이나 대문자가 들어가면 프로젝트 만들기가 거절된다).
3. 그 폴더에서 Claude Code를 연다. 터미널이라면 `cd ` 다음에 `snowpath` 폴더를 터미널 창으로 끌어다 놓고 Enter, 이어서 `claude`를 입력하고 Enter.
4. 3장의 1단계 프롬프트를 붙여 넣는다.

받은 자료 (`snowpath/docs/` 안)

| 파일 | 내용 |
|---|---|
| `눈길발자국_기획서.md` | 규칙, 화면, 문구의 기준 |
| `눈길발자국_프롬프트설계서.md` | 이 문서 |
| `눈길발자국_그림제작목록.md` | 나중에 바꿀 그림의 목록(선택 A). 그림이 없어도 앱은 도형 그림으로 완성된다 |
| `prototype.html` | 눌러 보는 시안. 브라우저로 끌어다 놓으면 열린다 |
| `kit/src/engine/engine.ts` | 참조 엔진 |
| `kit/src/engine/engine.golden.test.ts` | 엔진과 검증 자료를 대조하는 시험(19개) |
| `kit/src/engine/golden/snowpath_golden_v1.json` | 검증 자료(약 0.9MB) |

`kit/` 안의 파일은 1단계에서 AI 도구가 제자리(`src/`, `scripts/`)로 옮긴다.

## 2. 진행 방법

- 한 단계에 프롬프트 하나다. 회색 상자 안의 글을 그대로 붙여 넣는다. 이 파일이 저장소 안에 있으므로 "docs/눈길발자국_프롬프트설계서.md의 N단계 프롬프트대로 진행해 줘"라고만 해도 된다.
- 단계가 끝나면 AI의 보고에서 세 가지를 본다: `npm run check`가 통과했는지, 무엇이 달라졌는지, 확인하지 못했다고 한 것이 무엇인지.
- 화면을 볼 때: "개발 서버를 켜 줘"라고 하면 주소(보통 `http://localhost:3000`)를 알려 준다. 브라우저에서 그 주소를 연다. 견본 화면은 주소 끝에 `/lab`을 붙인다.
- 폰 크기로 볼 때(크롬): 화면에서 오른쪽 클릭 → 「검사」 → 검사 창 왼쪽 위의 기기 모양 단추(단축키 ⌘⇧M) → 위쪽의 크기 칸에 360과 640을 넣는다. 메뉴 이름은 화면을 보고 적은 것이 아니라 기억으로 적었다.
- 단계마다 "직접 확인할 것"을 본 뒤 다음 단계로 간다. 이상하면 5장의 프롬프트를 쓴다.
- 1단계가 끝나면 새 대화를 열고 2단계를 시작한다. 1단계에서 만든 작업 규칙(AGENTS.md)은 새 대화부터 읽힌다. 그 뒤에도 대화가 길어지면 새 대화로 옮긴다(H-7).
- 8단계 뒤부터는 단계가 끝날 때마다 자동으로 새로 배포된다. 폰에서도 같은 주소로 확인할 수 있다.

## 3. 단계별 프롬프트

### 1단계. 프로젝트 뼈대와 작업 규칙

목표: Next.js 프로젝트를 만들고, 받은 엔진과 검증 자료를 제자리에 놓고, 시험 19개가 통과하는 것을 확인한다.

```text
이 폴더(snowpath)에 「눈길 발자국」 앱의 뼈대를 만들어 줘. 지금 폴더에는 docs/만 있어.
docs/kit/src/engine/golden/snowpath_golden_v1.json은 0.9MB라서 열어 보지 마.

1. node -v로 Node 판을 확인해 줘. 22.12 이상이거나 24 이상이어야 해. 아니면 멈추고 알려 줘.
2. 이 폴더에 Next.js 프로젝트를 만들어 줘.
   npx create-next-app@latest . --ts --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --yes
   docs 폴더는 있어도 된다. 다른 파일 때문에 거절되면 지우지 말고 멈춰서 알려 줘.
3. 자료 옮기기: docs/kit/src/engine → src/engine, docs/kit/src/assets → src/assets, docs/kit/scripts → scripts.
   옮긴 뒤 docs/kit 폴더를 지워 줘. 파일 내용은 고치지 마.
4. 꾸러미 설치
   npm i zustand
   npm i -D vitest @types/node@^22
   (@types/node를 22로 올리지 않으면 vitest 설치가 버전 충돌로 실패한다.)
5. 설정
   - vitest.config.mts를 만든다(확장자가 .mts여야 경고가 없다). environment는 "node", include는 ["src/**/*.test.ts"].
   - next.config.ts에 output: "export"를 넣는다. cacheComponents와 partialPrefetching 줄이 있으면 지운다(정적 내보내기와 함께 쓰면 빌드가 실패한다). turbopack 설정은 그대로 둔다.
   - package.json의 scripts에 "test": "vitest run", "typecheck": "tsc --noEmit",
     "check": "npm run test && npm run typecheck && npm run lint && npm run build"를 넣는다.
     "engines": { "node": ">=22.12" }도 넣는다.
6. 작업 규칙
   - AGENTS.md에서 Next.js가 관리하는 블록(BEGIN과 END 주석 사이)은 그대로 둔다.
   - 그 아래에 docs/눈길발자국_프롬프트설계서.md의 "부록 1. 작업 규칙"에 있는 글을 그대로 붙인다.
   - CLAUDE.md를 새로 만든다. 내용은 @AGENTS.md 한 줄이다.
7. src/app/page.tsx는 "눈길 발자국" 제목만 보이는 임시 화면으로 바꾼다. layout.tsx의 lang은 "ko", 제목은 "눈길 발자국"으로 바꾼다. public/의 기본 그림은 지운다.
8. npm run check를 돌려서 결과를 알려 줘. 시험 19개가 모두 통과해야 해.
9. 통과하면 "1단계: 프로젝트 뼈대와 작업 규칙"으로 커밋해 줘.
```

직접 확인할 것

1. AI의 보고에 "시험 19개 통과"와 `npm run check` 통과가 있다.
2. "개발 서버를 켜 줘"라고 한 뒤 알려 준 주소를 열면 "눈길 발자국" 제목이 보인다.
3. Finder에서 `snowpath` 폴더를 보면 `AGENTS.md`, `CLAUDE.md`, `src`, `scripts`가 있고 `docs/kit`은 없다.

끝나면 새 대화를 열고 2단계로 간다.

### 2단계. 바탕 디자인과 화면 틀

목표: 색, 글꼴, 화면을 바꾸는 틀, 견본 화면을 만든다.

```text
바탕 디자인과 화면 틀을 만들어 줘. 먼저 기획서 8.1, 8.5, 9.8, 16장을 읽고, docs/prototype.html의 <style>(색 변수, 단추 모양)을 봐 줘.

1. 색: 기획서 8.5의 값 9개를 src/app/globals.css에 CSS 변수와 Tailwind 테마 색으로 정의한다. 어두운 화면 모드는 만들지 않는다(뼈대의 dark 관련 스타일은 지운다).
2. 글꼴: next/font/google로 Bagel_Fat_One(제목, 의태어)과 Gowun_Dodum(본문)을 넣는다. 둘 다 weight "400", subsets ["latin"], display "swap". 뼈대의 Geist 글꼴은 지운다.
3. 앱 틀: 주소는 "/" 하나만 쓰고 화면 전환은 상태로 한다(Zustand, src/store/). 화면은 src/screens/에 하나씩 둔다. 화면을 바꿀 때 history.pushState로 기록을 쌓고 popstate에서 앞 화면으로 돌아가게 해서, 폰의 뒤로 가기가 윗줄의 「뒤로」와 같게 동작하게 한다.
4. 화면에만 있는 말: 기획서 9.8의 표(L-01~L-16)를 src/screens/labels.ts에 옮긴다. 앞으로 단추 이름은 여기서만 가져온다.
5. 공통 부품: 주 단추, 보조 단추(높이 44 이상), 화면 윗줄(뒤로, 이름, 소리 단추 자리). 세로 폰 기준으로 가운데에 두고 최대 가로 460, 양옆 여백 16.
6. 임시 홈: 제목(TEXT['T-01'])과 "자유 눈길" 단추만 둔다. 단추는 아직 아무 일도 하지 않는다.
7. 견본 화면: src/app/lab/page.tsx. 개발 중에만 보이게 한다(production 빌드에서는 notFound()). 지금은 색 9개, 글꼴 두 가지, 단추를 늘어놓는다. 앞으로 단계마다 여기에 부품을 올려서 확인한다.
8. viewport는 width=device-width, initial-scale=1. 확대를 막지 않는다.
9. npm run check가 통과하면 "2단계: 바탕 디자인과 화면 틀"로 커밋해 줘.
```

직접 확인할 것

1. 주소 끝에 `/lab`: 색 9칸이 보이고, 제목 글꼴(둥글고 굵은 글씨)과 본문 글꼴이 서로 다르게 보인다.
2. 홈: 폰 크기(360×640)에서 내용이 가운데에 있고 옆으로 넘치지 않는다.

### 3단계. 악보

목표: 악보와 기호를 SVG로 그린다.

```text
악보를 그리는 부품을 만들어 줘. 먼저 기획서 6.1, 8.3의 아래 설명, 10장을 읽어 줘. 그리는 방법은 docs/prototype.html의 buildStage(오선 부분), glyph, glyphCentered, drawNotes, slurPath, markTop을 기준으로 삼아 줘.

1. src/stage/에 무대의 SVG 틀(viewBox "0 0 360 226")과 악보 층을 만든다. 치수는 한 파일(src/stage/geom.ts)에 모은다. 엔진에 있는 값(GEOM.X0, GEOM.W, GEOM.TH, GEOM.START_X)은 엔진에서 가져오고, 나머지는 기획서 10장의 표와 시안의 상수를 쓴다.
2. 기호 윤곽선은 src/assets/music-glyphs.json을 쓴다. 쓰는 법은 파일의 about에 있다.
3. 그릴 것
   - 오선 다섯 줄과 끝의 마디줄, 높은음자리표, 4/4 박자표
   - 4분음표 4개(머리와 아래로 향한 기둥)
   - 음표 머리 기호: 스타카토, 테누토(R-41), 악센트(R-42), 마르카토(R-43)
   - 이음줄(R-05, R-44): 잇달아 이어진 이음은 하나로 그린다
   - 가린 기호 ?(R-45)
   - 이음줄 자리의 점선 호(R-46)
   - 흐리게 겹쳐 그리는 정답 기호(기획서 8.3, 불투명도 35%)
4. 받는 값: 악보(엔진의 Spec), 기호를 가릴지, 이음 자리를 보일지, 흐리게 보일 정답(엔진의 Marking 또는 없음).
5. 견본 화면에 올릴 것
   (가) 가락 12개(MELODIES)를 기호 없이
   (나) 음높이 B4, C5, D5, E5 각각에 스타카토, 테누토, 악센트, 마르카토를 붙인 16가지
   (다) 이음줄 6가지(네 음 모두, 앞의 두 음, 뒤의 두 음, 가운데 두 음, 앞의 세 음, 뒤의 세 음)
   (라) 이음줄 안의 음에 악센트나 마르카토가 있는 경우 2가지
   (마) ? 가림, 이음 자리 점선, 흐린 정답
6. npm run check가 통과하면 "3단계: 악보"로 커밋해 줘.
```

직접 확인할 것 (`/lab`)

1. 점(스타카토)과 줄(테누토)이 음표 머리 바로 위에 있고, 오선의 줄에 걸치지 않고 칸 안에 있다.
2. `>`와 `^`는 오선 위쪽 바깥에 있다.
3. 이음줄이 음표 머리 위로 지나가고 `>`, `^`와 겹치지 않는다. "앞의 세 음"은 줄 하나로 그려진다.
4. `docs/prototype.html`을 브라우저로 열어 나란히 놓고 보면 악보가 같은 모양이다.

### 4단계. 눈길과 자국

목표: 눈길과, 소리의 모양인 자국을 그린다.

```text
눈길과 자국을 그리는 부품을 만들어 줘. 먼저 기획서 4장, 6.4, 10장의 눈길 줄을 읽어 줘. 그리는 방법은 시안의 buildStage(눈길 부분), shapeEl, drawPrints, drawTarget, setReveal, drawBadges를 기준으로 삼아 줘.

1. 눈길 층을 악보와 같은 SVG 안에 만든다(음표와 자국이 세로로 맞아야 한다): 눈길 바탕, 눈 표면, 박의 경계 점선, 원래 자국 층, 자국 층, 맞음·틀림 표시 층, 효과 층.
2. 자국 도형은 엔진의 printShapes(plan(spec))가 준 것만 그린다.
   - bar: 중심선(y 196)에 놓인 둥근 막대. x0부터 x1까지, 굵기 th.
   - wedge: x0에서 중심선 위아래로 h만큼 벌어져서 x1에서 막대 굵기(GEOM.TH)로 좁아지는 쐐기.
   - specks: x 둘레의 눈 튄 점 5개. 자리는 시안의 shapeEl과 같게.
3. 드러내기: 자국 층은 왼쪽부터 주어진 x까지만 보이게 한다(clipPath). 걷기에서 쓴다.
4. 원래 자국(발자국 탐정에서 쓴다): 같은 도형을 채운 모양과 점선 테두리 모양 두 가지로 그릴 수 있게 한다.
5. 맞음·틀림 표시: 음마다 ✓ 또는 ✗. 색과 모양을 함께 쓴다.
6. 견본 화면에 올릴 것
   (가) 한 마디 전체가 없음, 스타카토, 테누토, 레가토, 악센트, 마르카토인 6가지. specOf([], 0)과 specOf([{ kind, scope: 'ALL' }], 0)으로 만든다.
   (나) INTRO의 장면에 있는 틀(show) 가운데 표지판이 두 가지 이상인 것
   (다) 점선 테두리 모양, ✓✗ 표시, 드러내는 x를 움직이는 슬라이더
7. npm run check가 통과하면 "4단계: 눈길과 자국"으로 커밋해 줘.
```

직접 확인할 것 (`/lab`)

1. 여섯 가지 자국이 서로 달라 보인다: 스타카토는 점처럼 짧다. 테누토는 길지만 음마다 끊긴다. 레가토는 하나로 이어진다. 악센트는 굵게 시작해서 가늘어진다. 마르카토는 더 굵고 둘레에 점이 튀어 있다.
2. 자국의 왼쪽 끝이 음표 바로 아래에서 시작한다.
3. 슬라이더를 움직이면 자국이 왼쪽부터 드러난다.

### 5단계. 펭귄과 걷기

목표: 펭귄이 악보대로 걷고 자국이 따라 드러난다. 소리는 아직 없다.


```text

6. 자유 눈길의 표지판을 openKinds의 것으로 바꾼다.
7. 저장 값을 읽고 검사하고 쓰는 부분은 순수 함수로 떼어 Vitest 시험을 붙인다: 정상 값, 깨진 JSON, 모양이 다른 값, 저장할 수 없는 환경.

9. npm run check가 통과하면 "9단계: 기록 저장과 수업 링크"로 커밋해 줘.
```

H-1. 점검이 실패할 때

```text
npm run check가 실패해. 엔진과 검증 자료는 고치지 말고, 무엇이 왜 실패했는지 먼저 쉬운 말로 설명해 줘. 고칠 방법이 둘 이상이면 추천과 이유를 알려 주고, 내 확인을 받은 뒤에 고쳐 줘.
```

H-2. 화면이 기획서와 다를 때

```text
[화면 이름]에서 [무엇]이 [어떻게] 보여. 기획서 [절]에는 [이렇게] 되어 있어. 원인을 찾아 고쳐 줘. 엔진 함수의 값을 쓰지 않고 화면 쪽에서 계산한 곳이 있으면 엔진 함수로 바꿔 줘.
```

H-3. 폰 크기에서 넘치거나 잘릴 때

```text
360×640에서 [화면 이름]의 [무엇]이 화면 밖으로 넘쳐(또는 글자가 잘려). 기획서 8.2의 높이 표에 맞춰 고쳐 줘. 글자 크기는 본문 14, 보조 12보다 작게 하지 말고, 누르는 곳의 높이는 44보다 작게 하지 마. 무대의 가로세로 비율(360:226)은 그대로 둬.
```

H-4. 폰에서 소리가 안 날 때

```text
[아이폰 또는 안드로이드, 브라우저 이름]에서 소리가 안 나. 차례로 확인해 줘: 소리 단추의 상태, 첫 누름에서 AudioContext가 만들어지고 resume되는지, navigator.audioSession의 type, 전체 음량 값. 원인을 찾을 수 있게 /lab에 임시 표시(AudioContext의 state, sampleRate, outputLatency, baseLatency)를 달아 줘. 내가 폰에서 보고 값을 알려 줄게.
```

H-5. 소리가 잘 구분되지 않거나 찢어질 때

```text
폰에서 들어 보니 [악센트와 마르카토가 비슷하게 들려 / 마르카토 소리가 찢어져 / 스타카토가 너무 짧아서 잘 안 들려]. src/audio/tuning.ts의 값만 바꿔서 고쳐 줘. 엔진의 값(LEN, BEAT)은 바꾸지 마. 바꾸기 전에 어떤 값을 얼마로 바꿀지와 이유를 먼저 알려 줘. 가장 큰 진폭이 0.9를 넘지 않게 해 줘.
```

H-6. 소리와 걸음이 어긋날 때

```text
[기기와 이어폰 종류]에서 소리가 걸음보다 [빠르게 / 늦게] 들려. 그림을 늦추는 값(outputLatency, baseLatency)을 /lab에 보여 주고, 어긋남을 줄일 방법을 추천해 줘. 블루투스 이어폰에서는 완전히 맞추기 어렵다면 그렇게 알려 줘.
```

H-7. 새 대화에서 이어 갈 때

```text
AGENTS.md와 docs/눈길발자국_프롬프트설계서.md를 읽고, git log로 어느 단계까지 했는지 확인해 줘. 그다음 [N]단계를 진행해 줘.
```

H-8. AI가 엔진이나 검증 자료를 고쳤을 때

```text
엔진과 검증 자료는 고치면 안 돼. src/engine과 scripts/gen_golden.py를 1단계의 커밋 상태로 되돌려 줘. 화면 쪽에서 맞출 수 있으면 그렇게 하고, 정말 규칙을 바꿔야 한다면 멈추고 이유를 설명해 줘.
```

H-9. 방금 한 것을 되돌릴 때

```text
방금 단계에서 바꾼 것을 마지막 커밋 상태로 되돌려 줘. 되돌리기 전에 무엇이 사라지는지 먼저 알려 줘.
```

H-10. AI가 화면을 직접 보고 확인하게 할 때

```text
Playwright를 개발용으로 설치해서 360×640과 1280×800에서 [화면 이름]을 캡처하고, 캡처를 보고 넘침, 겹침, 잘림을 찾아 줘. 캡처 파일은 커밋하지 마.
```

## 6. 규칙이나 수치를 바꾸고 싶을 때

| 바꾸려는 것 | 고칠 곳 | 검증 자료 |
|---|---|---|
| 소리의 크기와 음색(기획서 11장의 표) | `src/audio/tuning.ts` | 그대로 |
| 색, 글꼴, 배치, 그림 | 화면 쪽 | 그대로 |
| 단추 이름 등 화면에만 있는 말(L-번호) | `src/screens/labels.ts`와 기획서 9.8 | 그대로 |
| 길이의 비율(R-12), 한 박의 길이, 자국의 치수, 걸음의 자세 | 엔진, 생성기, 기획서 | 다시 만든다 |
| 안내 문장(T-번호), 주문 문장, 걸음 배우기 대본 | 엔진, 생성기, 기획서 | 다시 만든다 |
| 문제 틀, 문제 수, 별의 기준, 잠금 | 엔진, 생성기, 기획서 | 다시 만든다 |

- "다시 만든다"인 것은 엔진(`src/engine/engine.ts`)과 생성기(`scripts/gen_golden.py`)를 같은 내용으로 함께 고친 뒤 `python3 scripts/gen_golden.py src/engine/golden/snowpath_golden_v1.json`으로 검증 자료를 다시 만들고 `npm test`로 대조한다. 기획서의 해당 절과 부록 F도 고친다.
- 두 구현을 따로 고쳐서 서로 맞는지 대조하는 것이 이 자료의 안전장치다. 한쪽만 고치거나 검증 자료를 손으로 고치면 안전장치가 사라진다.
- 이런 변경은 구상을 함께 한 Claude 대화로 돌아와 상의하는 쪽을 권한다. 다른 규칙에 미치는 영향을 함께 확인할 수 있다.

## 부록 1. 작업 규칙

1단계에서 아래 글을 AGENTS.md의 Next.js 블록 아래에 그대로 붙인다.

```markdown
## 눈길 발자국 — 작업 규칙

아티큘레이션(스타카토, 레가토, 악센트, 테누토, 마르카토)을 걸음과 발자국으로 배우는 학습 게임 웹앱이다. 사용자는 개발자가 아니다.

### 기준

- 무엇을 만드는지는 `docs/눈길발자국_기획서.md`가 기준이다(R = 규칙, T = 문구, L = 화면에만 있는 말, S = 화면, D와 P = 결정). 만드는 순서는 `docs/눈길발자국_프롬프트설계서.md`의 단계다.
- 사용자가 준 단계만 한다. 다음 단계의 일을 미리 하지 않는다.
- 기획서와 다르게 만들어야 하거나 기획서에 없는 것을 정해야 하면 멈추고 사용자에게 묻는다. 선택지, 추천, 이유를 함께 말한다.

### 엔진

- `src/engine/engine.ts`는 규칙의 원본이다. 고치지 않는다.
- 정답, 판정, 안내 문장, 주문 문장, 문제 뽑기, 별, 잠금, 자국 도형, 펭귄 자세, 소리 일정은 엔진 함수가 준 값만 쓴다. 화면 쪽에서 다시 계산하지 않는다(기획서 7.1, 7.3).
- `src/engine/golden/snowpath_golden_v1.json`은 약 0.9MB다. 열어서 읽지 않는다. 고치지 않는다. `src/engine/engine.golden.test.ts`와 `scripts/gen_golden.py`도 고치지 않는다.
- 엔진이 틀린 것 같으면 고치지 말고 사용자에게 알린다.

### 화면

- 화면의 문장은 엔진의 것(TEXT, NAME, MEANS, WALK_WORD, INTRO, 문장을 돌려주는 함수)을 쓴다. 엔진에 없는 단추 이름 등은 기획서 9.8의 표를 `src/screens/labels.ts`에 옮겨 쓴다. 새 문장을 지어내지 않는다.
- `docs/prototype.html`(시안)은 그리는 방법의 기준이다: 악보, 이음줄, 자국, 펭귄, 눈 퍼짐, 소리 합성, 색과 배치. 계산 함수는 시안의 것을 옮기지 말고 엔진 것을 쓴다(둘의 결과는 같다). 시안의 맨 끝에 있는 window.claude 관련 코드는 옮기지 않는다.
- 폴더는 기획서 16장을 따른다. `src/engine/`은 다른 폴더를 불러오지 않는다.
- 세로 폰 360×640이 기준이다. 누르는 곳의 높이는 44 이상.

### 기술

- Next.js 정적 내보내기(`output: "export"`), TypeScript strict, Tailwind CSS, Zustand, Vitest.
- 서버 코드, 실행 중의 외부 요청, 로그인, 분석 도구, 광고를 넣지 않는다.
- 새 꾸러미(npm 패키지)는 사용자에게 묻고 넣는다.
- Next.js에 관한 것은 위 블록의 안내대로 설치된 판의 문서(`node_modules/next/dist/docs/`)를 먼저 확인한다.

### 단계를 마칠 때

- `npm run check`(시험, 타입 검사, 형식 검사, 빌드)가 모두 통과해야 한다. 통과하지 못했으면 끝났다고 하지 않는다.
- 통과하면 단계 이름으로 커밋한다. 원격 저장소(origin)가 있으면 push도 한다.
- 보고는 한국어로, 쉬운 말로, 결론부터 쓴다. 달라진 것, 확인한 것, 확인하지 못한 것, 사용자가 직접 볼 것을 나눠 적는다. 화면을 직접 보지 못했으면 그렇게 적는다.
```

## 부록 2. 미리 해 본 것과 해 보지 못한 것

해 본 환경: 2026-11-16, Node 22.23.4, npm 10.9.9, create-next-app 16.4.6(Next.js 16.4.6, React 19.3.0, Tailwind CSS 4.3.3), Vitest 5.1.0, Zustand 5.1.0. 리눅스에서 해 봤고 맥에서는 해 보지 않았다.

해 본 것

- 1단계의 절차를 `docs`만 있는 빈 폴더에서 그대로 실행했다: 프로젝트 만들기, 자료 옮기기, 꾸러미 설치, 설정, `npm run check`. 시험 19개, 타입 검사, 형식 검사, 정적 빌드가 모두 통과했다.
- 그때 걸린 세 가지를 1단계 프롬프트에 넣었다.
  1. `npm i -D vitest`만 하면 버전 충돌로 실패한다(뼈대의 `@types/node`가 20이고 Vitest 5는 22 이상을 요구한다). `@types/node@^22`를 함께 설치한다. Vitest 5는 Node 22.12 이상도 요구한다.
  2. `vitest.config.ts`라는 이름이면 경고가 난다. `vitest.config.mts`로 한다.
  3. 뼈대의 기본 설정(`cacheComponents`, `partialPrefetching`)을 둔 채 `output: "export"`를 넣으면 빌드가 실패한다. 두 줄을 지운다.
- AGENTS.md의 Next.js 블록 아래에 글을 붙이고 개발 서버를 켰다 꺼도 붙인 글과 블록이 그대로였다.
- 2단계 가운데 두 가지: `next/font/google`로 두 글꼴을 넣고 빌드가 되는 것(글꼴 파일 187개가 결과물에 함께 들어간다), 견본 화면(`/lab`)이 개발 서버에서는 보이고 빌드 결과에서는 404가 되는 것.
- 엔진과 검증 자료는 기획서 7.4에 적은 대로 대조했다. 시안의 계산 함수(연주 계획, 자국, 붙이기, 판정, 펭귄 자세)도 검증 자료와 같았다(값 11,582개). 그래서 시안의 그리는 방법에 엔진의 값을 넣으면 시안과 같은 그림이 나온다.

해 보지 못한 것

- 2단계의 나머지와 3단계부터의 화면, 소리, 저장, 배포. 프롬프트대로 끝까지 만들어 보지 않았다.
- 실제 폰의 소리와 누르는 느낌, 아이폰 무음 스위치.
- 2장과 8단계에 적은 크롬, GitHub Desktop, Vercel의 메뉴와 단추 이름. 화면을 보고 적은 것이 아니다.
- 꾸러미의 판이 달라지면 걸리는 곳이 달라질 수 있다. 그때는 H-1을 쓴다.
